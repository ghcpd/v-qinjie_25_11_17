Built a reproducible evaluation harness that ships the structured test cases, comparison logic, and automation hooks for assessing an AI model’s detection of vulnerabilities and secrets exposure.

Evaluation Harness

Test vectors now live in evaluation/test_cases.py (lines 1-145), capturing SQL injection, XSS, command injection, secrets exposure, and edge cases (missing/null/malformed snippets) with expected JSON issue records.
evaluation/model_client.py (lines 1-44) defines a subprocess client that feeds JSON to any model command, validates the JSON list response, and allows plugging real models via --model-cmd or MODEL_COMMAND, while evaluation/mock_model.py (lines 1-17) returns the expected outputs for local development.
The CLI evaluator (evaluation/evaluator.py (lines 14-128)) orchestrates every test case, compares issue fields, documents mismatches, and writes a timestamped JSON report under reports/ for visibility.
Environment setup is captured in setup.sh (lines 1-9) and requirements.txt (lines 1-2), so you can bootstrap a venv with Python 3.9+ before running evaluations.
Runtime helpers run_tests.sh (lines 1-12) and run_tests.bat (lines 1-2) activate the harness, ensuring the reporter is always populated into reports/ (tracked via .gitkeep).
