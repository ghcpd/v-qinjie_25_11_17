I implemented a reproducible security scanner test harness and tests for detecting common vulnerabilities and secrets exposure. It includes code, tests, scripts, Docker support, and a CI workflow to enable reproducible evaluation.

Summary of what I added
- security_scanner.py — static-pattern based scanner that detects:
  - SQL Injection (string concatenation or interpolation in queries, f-strings, format, templated braces)
  - Command Injection (os.system/subprocess invocation plus unsafe concatenation)
  - XSS (innerHTML/document.write)
  - Exposed Secrets (hardcoded API keys, sk_test/AKIA/AIza and credential-like keys)
  - Scanner returns JSON with fields per issue: issue_type, description, recommended_fix, file, line, snippet
- __init__.py — package initializer for imports
- test_scanner.py — pytest test cases (includes edge cases: missing input, None, empty, malformed code)
  - Pre-built list driven tests with expected results
- conftest.py — ensures imports from repo root work during tests
- test_scanner.py — tests also check JSON output structure
- vuln_example.py — example file with multiple vulnerabilities
- generate_report.py — generates a detailed JSON report comparing expected vs detected issues (reports/test_report.json)
- scan_repo.py — scan the repository files and generate a JSON file of found issues (reports/repo_issues.json)
- run_tests.sh & run_tests.bat — scripts to run tests and generate reports locally
- setup.sh & setup.bat — local setup scripts for virtualenv and dependency install
- requirements.txt — pinned packages for reproducible installs (pytest etc.)
- Dockerfile — containerized environment for running tests and scanner reproducibly
- ci.yml — GitHub Actions CI configuration to run tests and generate an artifact with the test report
- README.md — instructions on setup, running tests and scanning

How the scanner & test harness works
- scan_source(source_str, filename) inspects each line and multi-line patterns using regex heuristics. For multi-line cases, it checks if both an invocation (os.system/subprocess) and an unsafe concatenation appear anywhere in the file.
- The returned JSON is:
  {
    "issues": [
      {
        "issue_type": "...",
        "description": "...",
        "file": "path or name",
        "line": 123,
        "snippet": "line content or short context",
        "recommended_fix": "..."
      }
    ]
  }
- The test harness (pytest) validates that the scanner finds vulnerabilities and respects safe patterns (parameterized queries and subprocess runs with argument lists).

Reproducible testing
- Local:
  - Run setup to install dependencies:
    - Linux / macOS: setup.sh
    - Windows: setup.bat
  - Run tests:
    - run_tests.sh (Linux/macOS) or run_tests.bat (Windows)
- Using Docker:
  - docker build -t sec-scanner .
  - docker run --rm -it sec-scanner bash
  - inside container: pytest -q
- CI:
  - GitHub Actions workflow at ci.yml runs tests and generates reports automatically.

Reports and output format
- JSON report format for each issue includes the requested fields:
  - Issue Type
  - Description
  - Recommended Fix
  - file, line, snippet
- generate_report.py generates a "reports/test_report.json" that includes summary (total/passed/failed) and an array with detailed results.

Edge cases included in tests
- Missing input (empty string, None)
- Null values: None input returns no issues
- Malformed code: the scanner attempts to detect templated SQL patterns even for malformed queries
- Safe usage checks: tests ensure no false positives for parameterized queries and subprocess list usage

Notes about heuristics and limitations
- The scanner is pattern-based: it uses heuristics and regexes rather than static program flow analysis; this is intentionally simple for demonstration and reproducibility.
- This scanner helps evaluate AI models for detection capability by providing a ground truth test harness. The rules attempt to minimize false positives for common safe patterns but are not perfect — extend the rules or use a static analysis library for more accurate detection.
